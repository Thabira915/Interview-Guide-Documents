AWS
======
IAM  - Manages users, roles, groups, and policies to control who can access which AWS resources and what actions they can perform.
S3  - Scalable object storage service used to store and retrieve any amount of data such as files, backups, logs, and static website content.
EC2  - Virtual server (compute instance) in AWS that lets you run applications on scalable infrastructure without owning physical hardware.
Elastic BeanStalk - PaaS service that automatically handles deployment, capacity provisioning, load balancing, and scaling of your application.
AWS Lambda  - Serverless compute service that runs your code in response to events without requiring you to provision or manage servers.
AWS Dynamo DB  - Fully managed NoSQL database service offering single-digit millisecond latency with automatic scaling and high availability.
AWS Secret Manager  - Securely stores, rotates, and manages sensitive information like database passwords, API keys, and credentials.
AWS Certificate Manager  - Manages provisioning, renewal, and deployment of SSL/TLS certificates for secure HTTPS communication.
AWS RDS — Managed relational database service supporting engines like MySQL, PostgreSQL, MariaDB, Oracle, and SQL Server with automated backups and patching.
SQS — Fully managed message queue service used to decouple and scale microservices through asynchronous communication between components.
SNS — Pub/Sub notification service that sends messages to multiple subscribers simultaneously via email, SMS, Lambda, or SQS.
EKS — AWS managed Kubernetes service that simplifies deploying, managing, and scaling containerized applications using Kubernetes.
ECS — AWS native container orchestration service for running, stopping, and managing Docker containers on a cluster.
Aurora DB — High-performance, fully managed relational database compatible with MySQL and PostgreSQL, offering up to 5x MySQL speed.
AWS MSK — Fully managed Apache Kafka service that handles cluster provisioning, configuration, and maintenance for real-time streaming applications.
Route 53 — Highly available and scalable AWS DNS service used for domain registration, routing, and health checking.
CloudFront — Content Delivery Network (CDN) service that delivers data, videos, and applications globally with low latency using edge locations.
Fargate — Serverless compute engine for running containers without managing the underlying EC2 server infrastructure.
ELB (Elastic Load Balancer) — Automatically distributes incoming application traffic across multiple targets like EC2 instances for high availability and fault tolerance.
ElastiCache — Fully managed in-memory caching service supporting Redis and Memcached to improve application read performance.
CloudWatch — Monitoring and observability service used to collect metrics, logs, and alarms for AWS resources and applications.
CloudTrail — Governance and auditing service that records and logs all API calls and account activity across your AWS infrastructure.

Kubernetes
=============
Pod — Smallest deployable unit in Kubernetes that encapsulates one or more containers sharing the same network and storage.
Node — A worker machine (VM or physical server) in a Kubernetes cluster where pods are scheduled and run.
Cluster — A set of master and worker nodes that together run and manage containerized applications.
Deployment — Manages pod replicas and enables rolling updates and rollback.
ReplicaSet — Ensures a specified number of identical pod replicas are always running at any given time.
Service — Provides a stable network endpoint and load balancing to expose pods internally or externally.
ClusterIP — Internal service accessible only inside the cluster.
NodePort — Exposes service externally using a port on each node.
LoadBalancer — Exposes service externally using cloud provider load balancer.
Ingress — Manages external HTTP/HTTPS routing to services using rules.
ConfigMap — Stores non-sensitive configuration data as key-value pairs.
Secret — Securely stores sensitive data like passwords and tokens.
Namespace — Logical isolation used to organize resources inside a cluster.
kubectl — CLI tool used to interact with Kubernetes clusters.
etcd — Distributed key-value store used to store Kubernetes cluster state.
Kubelet — Agent running on each node that manages pods and containers.
Kube-Proxy — Handles networking and traffic routing inside the cluster.
Control Plane (Master Node) — The brain of the Kubernetes cluster that manages scheduling, health monitoring, and overall cluster decisions.
Scheduler — Control plane component that decides which worker node a newly created pod should run on based on resource availability.
API Server — Entry point for all Kubernetes API requests.
Controller Manager — Runs built-in controllers (like node, replication, endpoint controllers) to maintain the desired cluster state.
StatefulSet — Manages stateful applications with stable identity and storage.
DaemonSet — Ensures exactly one pod runs on every node in the cluster, commonly used for log collectors and monitoring agents.
Job — Runs a task until completion successfully.
CronJob — Runs Jobs on a scheduled basis using cron syntax, useful for periodic tasks like backups or report generation.
Persistent Volume (PV) — A piece of storage in the cluster provisioned by an admin or dynamically, independent of any pod lifecycle.
Persistent Volume Claim (PVC) — A request made by a pod for a specific amount and type of storage from available Persistent Volumes.
StorageClass — Defines how storage is dynamically provisioned including the provider, type, and reclaim policy.
Helm — Kubernetes package manager that uses charts to define, install, and upgrade complex Kubernetes applications.
Horizontal Pod Autoscaler (HPA) — Automatically scales pods based on CPU/memory usage.
Taint — Restricts pods from scheduling on certain nodes unless tolerated.
Toleration — Allows pods to run on tainted nodes.
Label — Key-value metadata attached to Kubernetes objects to identify, group, and select resources.
Selector — Used to filter and match Kubernetes resources based on their labels for grouping or targeting.
Sidecar Container — A helper container that runs alongside the main application container in the same pod to extend functionality.
Init Container — A container that runs and must complete successfully before the main application container starts.
Liveness Probe — Periodically checks if a container is still running and restarts it if the check fails.
Readiness Probe — Checks if a pod is ready to serve traffic and removes it from the service endpoint if the check fails.
Resource Limits — Maximum CPU and memory a container is allowed to use, enforced by the Kubernetes scheduler.
Resource Requests — Minimum CPU and memory guaranteed to a container, used by the scheduler to place pods on nodes.
RBAC — Role-Based Access Control system that regulates which users or service accounts can perform which actions on Kubernetes resources.
Network Policy — Kubernetes resource that defines rules for controlling inbound and outbound pod-to-pod network traffic.
Minikube — Local single-node Kubernetes cluster tool for development and testing on a personal machine.
EKS — AWS managed Kubernetes service.

kafka
======
Kafka — Distributed event streaming platform used for real-time data pipelines and messaging.
Producer — Application that sends messages to Kafka topics.
Consumer — Application that reads messages from Kafka topics.
Topic — Logical channel or category to which producers publish messages and from which consumers read.
Partition — A topic is divided into partitions for parallel processing, scalability, and ordered message storage.
Broker — A Kafka server that stores messages and serves producer and consumer requests within the cluster.
Cluster — Group of Kafka brokers working together.
Offset — A unique sequential ID assigned to each message within a partition to track its position.
Consumer Group — Group of consumers sharing message consumption workload.
Replication — The process of copying partition data across multiple brokers to ensure fault tolerance and data durability.
Leader Partition — The primary replica of a partition responsible for all reads and writes; other replicas follow it.
Follower Partition — A replica that continuously syncs data from the leader partition and takes over if the leader fails.
ZooKeeper — External coordination service previously used by Kafka for managing broker metadata, leader election, and configuration.
KRaft — Kafka's built-in consensus protocol that replaces ZooKeeper for managing cluster metadata since Kafka 2.8+.
Retention Period — Time Kafka keeps messages before deletion.
ACK — Acknowledgment setting on a producer that controls how many broker replicas must confirm receipt before the write is considered successful.
ISR (In-Sync Replica) — Replicas fully synced with leader partition.
Lag — The gap between the latest offset in a partition and the last offset processed by a consumer; indicates how far behind a consumer is.
Rebalancing — The process of redistributing partition assignments among consumers in a group when members join or leave.
Serializer — Converts objects into bytes before sending to Kafka.
Deserializer — Converts Kafka bytes back into objects for consumers.
Idempotent Producer — A producer configuration that ensures each message is written exactly once to a partition, preventing duplicates on retry.
Exactly Once Semantics — Guarantees that a message is produced, delivered, and consumed exactly once with no duplication or data loss.
At Least Once — Messages may duplicate but are never lost.
At Most Once — Messages may be lost but never duplicated.
Dead Letter Topic (DLQ) — A special Kafka topic used to capture messages that failed processing so they can be analyzed or reprocessed.
Kafka Connect — Tool for integrating Kafka with external systems/databases.
Kafka Streams — Library for stream processing directly within Kafka applications.
Schema Registry — Centralized service that stores and enforces Avro/JSON/Protobuf schemas for Kafka message serialization consistency.
Compaction — Log compaction strategy that retains only the latest message per key in a partition, removing outdated duplicates.
Batching — Producer sending multiple messages together for better performance.
Throughput — Number of messages processed per second.
Consumer Polling — Consumers repeatedly call the poll() method to fetch batches of messages from Kafka brokers.
Commit Offset — The action of saving the offset of the last successfully processed message so the consumer can resume correctly after a restart.
Synchronous Communication — Sender waits for immediate response.
Asynchronous Communication — Sender continues without waiting for response.
Event Streaming — Continuous flow and processing of real-time events/data.
Back Pressure — A condition where the consumer cannot process messages as fast as the producer sends them, causing queue build-up.
Ordering Guarantee — Kafka guarantees message order only within a single partition, not across partitions of a topic.
Horizontal Scaling — Adding more partitions or brokers to a Kafka cluster to increase throughput and capacity.
Fault Tolerance — Kafka's ability to continue operating correctly even when one or more brokers fail, due to replication.

Microservices
=================
Microservices — Architecture where applications are split into small independently deployable services.
Monolith — Single large application where all modules are tightly coupled.
Service Discovery — Service Discovery — A mechanism that allows services to dynamically find and communicate with each other without hardcoded addresses.
Eureka Server — Netflix OSS service registry where microservices register themselves and discover other services at runtime.
API Gateway — Single entry point for all client requests, handling routing, authentication, rate limiting, and load balancing.
Load Balancing — Distributes incoming requests evenly across multiple service instances to avoid overloading any single instance.
Feign Client — Declarative REST client for service-to-service communication.
REST API — Communication style using HTTP methods like GET, POST, PUT, DELETE.
Synchronous Communication — A microservice directly calls another and waits for a response before proceeding.
Asynchronous Communication — A microservice sends an event or message to a queue/broker without waiting for the consumer to process it.
Circuit Breaker — A resilience pattern that stops forwarding requests to a failing service and returns a fallback to prevent cascading failures.
Retry Mechanism — Automatically re-attempts a failed service call a configured number of times before giving up.
Fallback — A predefined alternative response or action executed when a service call fails or times out.
Resilience4j — A lightweight Java fault-tolerance library providing circuit breaker, retry, rate limiter, and bulkhead patterns.
Distributed Tracing — Technique for tracking and visualizing the full journey of a request as it passes through multiple microservices.
Sleuth — Spring Cloud library that automatically adds trace IDs and span IDs to logs for distributed request tracing.
Zipkin — Open-source distributed tracing system that collects, stores, and visualizes timing data across microservices.
Centralized Logging — Aggregating logs from all microservices into a single platform for unified monitoring and debugging.
ELK Stack — Combination of Elasticsearch (search), Logstash (ingestion), and Kibana (visualization) for centralized log management.
Config Server — Centralized service that provides externalized configuration for all microservices from a single source (e.g., Git).
Spring Cloud Config — Externalized centralized configuration service.
Docker — Containerization platform that packages an application and its dependencies into a portable image that runs consistently anywhere.
Containerization — Bundling application code, libraries, and runtime into a container for consistent, environment-independent deployment.
Kubernetes — Open-source container orchestration platform for automating deployment, scaling, and management of containerized applications.
Horizontal Scaling — Increasing the number of service instances to handle more traffic instead of upgrading server hardware.
Vertical Scaling — Increasing the CPU or memory capacity of an existing server to improve its performance.
Database Per Service — Design principle where each microservice manages its own dedicated database to maintain loose coupling.
Distributed Transaction — A transaction that spans multiple microservices or databases and must remain consistent across all of them.
Saga Pattern — Manages distributed transactions by breaking them into a series of local transactions with compensating actions on failure.
Event-Driven Architecture — Design pattern where services communicate by producing and consuming events through a message broker.
Strangler Fig Pattern — Gradually replaces a legacy monolith by routing new functionality to microservices while keeping the old system running in parallel until fully replaced.
Outbox Pattern — Ensures atomicity between a database write and a message publish by writing the event to an outbox table in the same transaction, then publishing it asynchronously.
Sidecar Pattern — Deploys a helper process (e.g., logging agent, proxy) alongside the main service container in the same pod to offload cross-cutting concerns.
Aggregator Pattern — A service that calls multiple downstream microservices, collects their responses, and returns a single combined result to the client.
Chained Microservice Pattern — A request passes through a sequence of services in a chain where each service processes and passes output to the next.
Event Sourcing — Persists the state of an entity as an ordered sequence of immutable domain events rather than the current state, enabling full audit trail and replay.
Two-Phase Commit (2PC) — A distributed transaction protocol where a coordinator asks all participants to prepare, then commits only if all agree; avoided in microservices due to tight coupling and blocking.
Compensating Transaction — An operation that semantically undoes a previously completed step in a saga when a later step fails, restoring business consistency without true rollback.
Service Mesh Pattern — Offloads inter-service communication concerns (load balancing, retries, mTLS, tracing) to a dedicated infrastructure layer like Istio, freeing services from that logic.
Backends for Frontends (BFF) — Creates a separate API gateway/backend tailored for each type of client (mobile, web, third-party), avoiding a one-size-fits-all API.
Throttling Pattern — Limits the rate at which a service processes requests from a client to protect against overload and ensure fair resource usage.
Rate Limiting — Enforces a maximum number of requests a client can make in a given time window, commonly implemented at the API Gateway.
Health Check Pattern — Each microservice exposes a /health endpoint that reports its liveness and readiness status, used by load balancers and orchestrators to route traffic.
Leader Election Pattern — When multiple instances of a service run concurrently, one is elected as leader to perform a singleton task (e.g., scheduled job), preventing duplication.
Choreography (Saga) — Services react to domain events published by other services without a central coordinator; each service knows what to do when it receives a specific event.
Orchestration (Saga) — A central saga orchestrator explicitly tells each service what to do and handles compensation logic when a step fails.
API Composition Pattern — A query is handled by calling multiple services and joining the results in memory at the API layer, used when data spans multiple service databases.
Gateway Aggregation — The API Gateway aggregates multiple fine-grained service calls into a single response, reducing client round trips.
Gateway Offloading — Cross-cutting concerns like authentication, SSL termination, logging, and rate limiting are offloaded to the API Gateway instead of each service.
Client-Side Load Balancing — The client fetches the service instance list from the registry and decides which instance to call (e.g., Ribbon, Spring Cloud LoadBalancer).
Server-Side Load Balancing — A load balancer sits between the client and service instances and routes requests, hiding instance details from the client.
Retry with Exponential Backoff — On failure, the client waits an exponentially increasing delay before each retry attempt to avoid overwhelming a recovering service.
Idempotent Consumer — A message consumer that safely handles duplicate messages by checking whether a message has already been processed before acting on it.
Kafka — Distributed event streaming platform for asynchronous communication.
RabbitMQ — Message broker used for asynchronous messaging.
Idempotency — Same request produces same result even if repeated multiple times.
OAuth2 — Authorization framework for secure API access.
JWT Token — A compact, self-contained token used for stateless authentication by encoding user claims in a signed JSON structure.
Stateless Service — A service that does not retain any client session data between requests; each request is fully self-contained.
Blue-Green Deployment — Deployment strategy maintaining two identical environments (blue/green) and switching traffic to the new version with zero downtime.
Canary Deployment — Gradually rolling out a new version to a small percentage of users to validate it before full release.
CI/CD — Automated pipeline for continuously integrating code changes, running tests, and deploying to production.
Jenkins — Open-source automation server widely used to create CI/CD pipelines for building, testing, and deploying applications.
Prometheus — Open-source monitoring system that scrapes and stores time-series metrics from services and infrastructure.
Grafana — Visualization tool used to build dashboards and alerts on top of metrics from sources like Prometheus.
OpenAPI/Swagger — Specification and toolset for designing, documenting, and testing RESTful APIs in a standardized way.
Service Mesh — Dedicated infrastructure layer handling service-to-service communication, security, and observability (e.g., Istio).
Istio — Open-source service mesh that manages traffic, enforces policies, and provides observability for Kubernetes-based microservices.
gRPC — High-performance RPC framework using HTTP/2 and Protocol Buffers for efficient, strongly-typed inter-service communication.
CAP Theorem — Distributed systems can guarantee only two of Consistency, Availability, and Partition Tolerance.
Bulkhead Pattern — Isolates failures to prevent entire system impact.
CQRS — Command Query Responsibility Segregation; separates read (query) and write (command) models for scalability and clarity.
Eventual Consistency — Data becomes consistent over time across services.

Docker
===============
Docker Image — A read-only, layered template built from a Dockerfile that contains the application code, runtime, libraries, and configuration needed to create a container.
Docker Container — A running instance of a Docker image; an isolated, lightweight process with its own filesystem, network, and process space.
Dockerfile — A plain-text script containing a sequence of instructions (FROM, RUN, COPY, CMD, etc.) that Docker uses to build an image automatically.
Docker Hub — A public cloud-based registry for storing, sharing, and pulling Docker images; the default registry used by the Docker CLI.
Docker Registry — A storage and distribution system for Docker images; can be public (Docker Hub) or private (AWS ECR, Harbor, GitLab Registry).
docker build — Reads a Dockerfile and builds a new Docker image layer by layer, tagging it with a name and version.
docker run — Creates and starts a new container from a specified image, optionally mapping ports, volumes, and environment variables.
docker pull — Downloads a Docker image from a registry to the local machine without running it.
docker push — Uploads a locally built Docker image to a remote registry for sharing or deployment.
docker ps — Lists all currently running containers; use docker ps -a to include stopped containers.
docker stop — Gracefully stops a running container by sending a SIGTERM signal followed by SIGKILL if it does not stop in time.
docker rm — Removes one or more stopped containers from the local system.
docker rmi — Deletes one or more Docker images from the local image cache.
docker exec — Runs a command inside an already running container, commonly used to open an interactive shell for debugging.
docker logs — Fetches and displays the stdout/stderr logs output by a running or stopped container.
docker inspect — Returns detailed low-level JSON information about a container, image, or network including configuration and state.
docker images — Lists all Docker images stored locally along with their tag, image ID, and size.
docker-compose — A tool for defining and running multi-container Docker applications using a docker-compose.yml file with a single command.
docker-compose.yml — A YAML file that describes the services, networks, and volumes for a multi-container application managed by Docker Compose.
docker-compose up — Builds, creates, and starts all containers defined in the docker-compose.yml file in the correct dependency order.
docker-compose down — Stops and removes all containers, networks, and optionally volumes defined in the docker-compose.yml file.
Layer — Each instruction in a Dockerfile creates an immutable read-only layer; Docker caches layers to speed up subsequent builds.
Layer Caching — Docker reuses unchanged layers from previous builds, significantly reducing build time by only rebuilding layers that changed.
Base Image — The starting image specified in the FROM instruction of a Dockerfile on which all subsequent layers are stacked.
Multi-Stage Build — A Dockerfile technique using multiple FROM instructions to separate build and runtime stages, producing a smaller, cleaner final image.
Entrypoint — The ENTRYPOINT instruction in a Dockerfile defines the executable that always runs when the container starts; arguments from CMD are appended.
CMD — Provides default arguments or the default command to run in a container; can be overridden at docker run time.
EXPOSE — Documents which port the containerized application listens on at runtime; does not publish the port to the host.
Port Mapping (-p) — Maps a host machine port to a container port so external traffic can reach the containerized application.
Volume — A persistent, managed storage unit that exists outside the container's filesystem and survives container restarts and deletions.
Bind Mount — Mounts a specific directory from the host machine directly into the container, useful for development with live code reloading.
Docker Network — A virtual network that allows containers to communicate with each other securely and in isolation from the host or other networks.
Bridge Network — Default Docker network driver that creates an isolated internal network where containers on the same host can communicate.
Host Network — A network mode where the container shares the host machine's network stack directly, with no network isolation.
Overlay Network — Docker network driver that enables containers running on different Docker hosts (in a Swarm) to communicate securely.
ENV — Dockerfile instruction that sets environment variables inside the image, accessible to the application at runtime.
ARG — Dockerfile instruction that defines build-time variables passed with --build-arg; not available in the running container.
Docker Swarm — Docker's built-in native clustering and orchestration tool for deploying and managing services across multiple Docker hosts.
Docker Desktop — A GUI application for macOS and Windows that bundles Docker Engine, Docker CLI, Docker Compose, and Kubernetes in one install.
Docker Context — A configuration that tells the Docker CLI which Docker Engine to connect to (local, remote, or cloud-based).
Healthcheck — A Dockerfile or Compose instruction that defines a command Docker runs periodically to verify the container is still healthy.
Container Orchestration — Automated management of container lifecycle including scheduling, scaling, networking, and self-healing across a cluster.
ECR (Elastic Container Registry) — AWS's fully managed private Docker container registry for storing, managing, and deploying container images securely.
Image Tag — A label (e.g., latest, v1.0.0) appended to an image name to identify a specific version of that image.
docker tag — Creates an additional tag/alias for an existing local image, typically used before pushing to a registry with a new name or version.
docker network ls — Lists all Docker networks currently configured on the host.
docker volume ls — Lists all Docker volumes currently created on the host.
docker system prune — Removes all stopped containers, unused networks, dangling images, and optionally unused volumes to free disk space.
Dangling Image — An untagged image layer that is no longer referenced by any named image, typically left over from builds; safely removable.
Container Lifecycle — The sequence of states a container passes through: Created, Running, Paused, Stopped, and Removed.
Immutable Infrastructure — A deployment philosophy where containers are never modified after deployment; changes are made by replacing containers with new images.
Docker Daemon — The background service (dockerd) running on the host that manages images, containers, networks, and volumes via the Docker API.
Docker CLI — The command-line client (docker) that communicates with the Docker Daemon via REST API to execute user commands.
Namespace — Linux kernel feature used by Docker to isolate container processes, file systems, network stacks, and user IDs from each other and the host.
cgroups (Control Groups) — Linux kernel feature used by Docker to limit and monitor CPU, memory, and I/O resource usage per container.
Union File System — A layered filesystem (e.g., OverlayFS) that Docker uses to stack image layers efficiently without duplicating data.

Multithreading
===================
Multithreading — Executing multiple threads concurrently within a process.
Thread — Smallest independent execution unit inside a process.
Process — An independent program in execution with its own dedicated memory space, resources, and at least one thread.
Concurrency — Managing multiple tasks simultaneously.
Parallelism — Executing multiple tasks literally at the same time.
Main Thread — Default thread where Java program execution starts.
Thread Lifecycle — States through which a thread passes during execution.
New State — Thread created but not started.
Runnable State — Thread ready or running on CPU.
Blocked State — Thread waiting for monitor lock.
Waiting State — Thread waiting indefinitely for another thread action.
Timed Waiting — Thread waiting for specified time duration.
Terminated State — Thread execution completed.
Thread Class — Java class used to create threads by extending it.
Runnable Interface — Preferred way of creating threads using run() method.
Callable Interface — Similar to Runnable but returns result and throws exceptions.
Future — Represents result of asynchronous computation.
Executor Framework — Framework managing thread creation and pooling.
Thread Pool — Collection of reusable worker threads.
Executors Class — Factory class for creating thread pools.
Fixed Thread Pool — Thread pool with fixed number of threads.
Cached Thread Pool — Dynamically creates reusable threads as needed.
Single Thread Executor — Executes tasks sequentially using one thread.
Scheduled Executor Service — Executes tasks after delay or periodically.
start() — Starts new thread execution.
run() — Contains thread execution logic.
sleep() — Pauses thread execution temporarily.
join() — Waits for another thread to complete.
yield() — Suggests scheduler pause current thread execution.
Daemon Thread — Background thread running until user threads finish.
User Thread — Foreground thread keeping JVM alive.
Synchronization — Controlling shared resource access between threads.
Synchronized Method — Locks entire method for one thread at a time.
Synchronized Block — Locks only specific critical section of code.
Monitor Lock — Internal lock used by synchronized keyword.
Race Condition — Multiple threads updating shared data unpredictably.
Critical Section — Code section accessing shared resources.
Thread Safety — Code behaving correctly under concurrent execution.
Deadlock — Threads waiting forever for each other’s locks.
Starvation — Thread never getting CPU/resources due to higher-priority threads.
Livelock — Threads continuously reacting without making progress.
wait() — Releases lock and waits for notification.
notify() — Wakes one waiting thread.
notifyAll() — Wakes all waiting threads.
volatile Keyword — Ensures variable visibility across threads.
Atomic Variable — Thread-safe variable supporting atomic operations.
AtomicInteger — Thread-safe integer supporting atomic updates.
ReentrantLock — Advanced explicit locking mechanism.
ReadWriteLock — Separate locks for read and write operations.
Semaphore — Controls number of threads accessing resource simultaneously.
CountDownLatch — Allows threads to wait until tasks complete.
CyclicBarrier — Synchronizes threads reaching common barrier point.
ForkJoinPool — Framework for divide-and-conquer parallel tasks.
CompletableFuture — Advanced asynchronous programming support.
ConcurrentHashMap — Thread-safe high-performance hashmap.
CopyOnWriteArrayList — Thread-safe list optimized for read-heavy operations.
BlockingQueue — Queue supporting thread-safe producer-consumer operations.
Producer-Consumer Problem — Synchronization problem between producing and consuming threads.
Context Switching — CPU switching execution between threads/processes.
Thread Priority — Suggests execution importance to scheduler.
Immutable Object — Object whose state cannot change after creation.
ThreadLocal — Creates thread-specific isolated variable copies.
Parallel Stream — Java Stream API processing data concurrently.
Fork-Join Framework — Parallel execution framework splitting tasks recursively.
CAS (Compare And Swap) — Atomic operation used in lock-free programming.
Busy Waiting — Thread continuously checking condition wasting CPU cycles.
Lock Contention — Multiple threads competing for same lock.
Visibility Problem — One thread unable to see updated variable changes.
Memory Leak in Threads — Resources not released properly by threads.
CPU Bound Task — Task heavily dependent on CPU processing.
IO Bound Task — Task mainly waiting for I/O operations.

Java 8 
=============
Java 8 — Major Java release introducing functional programming features.
Lambda Expression — Anonymous function enabling concise functional-style code.
Functional Interface — Interface containing exactly one abstract method.
@FunctionalInterface — Annotation ensuring interface has one abstract method only.
Predicate — Functional interface testing condition and returning boolean.
Function — Functional interface transforming input into output.
Consumer — Functional interface accepting input without returning value.
Supplier — Functional interface supplying values without input.
Method Reference — Shorter syntax referring existing methods using ::.
Stream API — A powerful API for processing sequences of elements in a functional, declarative style with lazy evaluation.
Intermediate Operation — A Stream operation (e.g., filter, map) that returns a new Stream and is evaluated lazily.
Terminal Operation — A Stream operation (e.g., collect, forEach) that triggers the pipeline and produces a final result.
filter() — Selects elements matching condition.
map() — Intermediate operation that transforms each element into another form using a provided Function.
flatMap() — Intermediate operation that flattens a stream of streams (or collections) into a single stream.
reduce() — Terminal operation that combines all stream elements into a single result using an accumulator function.
collect() — Terminal operation that converts stream elements into a collection or other container using a Collector.
forEach() — Iterates through stream elements.
distinct() — Removes duplicate elements from stream.
sorted() — Intermediate operation that returns a stream with elements sorted in natural or custom order.
limit() — Restricts number of stream elements.
skip() — Skips specified number of elements.
findFirst() — Returns first matching element.
findAny() — Returns any matching element.
anyMatch() — Checks if any element matches condition.
allMatch() — Checks if all elements match condition.
noneMatch() — Checks if no elements match condition.
Optional Class — Container avoiding NullPointerException.
Optional.of() — Creates an Optional with a non-null value; throws NullPointerException if the value is null.
Optional.ofNullable() — Creates an Optional that may hold a null value without throwing an exception.
Optional.empty() — Creates empty Optional object.
isPresent() — Checks if Optional contains value.
orElse() — Returns default value if Optional empty.
orElseGet() — Lazily returns default value using Supplier.
orElseThrow() — Throws exception if Optional empty.
ifPresent() — Executes logic if Optional contains value.
Default Method — Interface method with implementation.
Static Method in Interface — Utility method defined inside interface.
Date and Time API — Improved immutable date/time handling introduced in Java 8.
LocalDate — Represents date without time.
LocalTime — Represents time without date.
LocalDateTime — Represents both date and time together without timezone information.
ZonedDateTime — Represents a full date, time, and timezone, useful for timezone-aware applications.
Instant — Represents timestamp in UTC.
Parallel Stream — Processes stream elements concurrently using multiple threads.
Sequential Stream — Processes elements one by one.
Collectors — Utility class for collecting stream results.
groupingBy() — Groups stream elements based on condition/key.
partitioningBy() — Splits elements into true/false groups.
joining() — Collector that concatenates stream elements into a single String with optional delimiter, prefix, and suffix.
counting() — Collector that counts the number of elements in the stream.
mapping() — Collector that applies a mapping function before collecting into another collector.
min() — Terminal operation that returns the minimum element according to a Comparator, wrapped in Optional.
max() — Terminal operation that returns the maximum element according to a Comparator, wrapped in Optional.
sum() — Terminal operation on numeric streams (IntStream, LongStream, DoubleStream) that calculates the total of all elements.
Stream Pipeline — A chain of source, intermediate operations, and a terminal operation executed as a single unit lazily.
Lazy Evaluation — Intermediate operations in a stream are not executed until a terminal operation is invoked.
Short Circuiting — A stream optimization where processing stops as soon as the result can be determined (e.g., findFirst, anyMatch).
Comparator.comparing() — Simplifies object sorting using fields.
forEachOrdered() — Maintains encounter order during parallel stream processing.
peek() — Performs action during stream processing mainly for debugging.
Double Colon Operator (::) — Syntax used for method references.
Nashorn Engine — JavaScript engine introduced in Java 8.
CompletableFuture — Provides a rich API for composing asynchronous computations with methods like thenApply, thenCompose, and exceptionally.
Base64 Encoder/Decoder — Utility for Base64 encoding and decoding.

Spring Security
=====================
SecurityFilterChain — The primary Spring Security 6+ configuration bean that defines the HTTP security rules, replacing the deprecated WebSecurityConfigurerAdapter.
WebSecurityConfigurerAdapter — The older (deprecated since Spring Security 5.7) base class overridden to customize HTTP security, authentication, and authorization rules.
HttpSecurity — A builder API used inside SecurityFilterChain to configure URL access rules, login/logout, CSRF, CORS, session management, and filter chains.
Filter Chain — A sequence of security filters (e.g., UsernamePasswordAuthenticationFilter, JwtFilter) that every HTTP request passes through before reaching the controller.
OncePerRequestFilter — A base class for writing a custom security filter that guarantees it executes exactly once per HTTP request, commonly used for JWT validation.
UsernamePasswordAuthenticationFilter — A built-in Spring Security filter that intercepts login requests, extracts credentials, and delegates to the AuthenticationManager.
AuthenticationManager — The core interface responsible for processing an Authentication object and returning a fully authenticated object or throwing an exception.
AuthenticationProvider — A strategy interface that performs a specific authentication mechanism (e.g., DaoAuthenticationProvider for username/password).
DaoAuthenticationProvider — The default AuthenticationProvider that loads user details from a UserDetailsService and validates the password using a PasswordEncoder.
UserDetailsService — A core interface with a single method loadUserByUsername() that fetches user data from a data source for authentication.
UserDetails — An interface representing a user with fields for username, password, authorities, and account status flags used by Spring Security.
UserDetailsImpl — A common custom implementation of UserDetails that maps application User entity fields to the Spring Security user model.
GrantedAuthority — An interface representing a permission or role (e.g., ROLE_ADMIN, ROLE_USER) granted to an authenticated user.
SecurityContext — A holder for the current user's authentication details (Authentication object) that is accessible throughout the request lifecycle.
SecurityContextHolder — A static class that stores and provides access to the SecurityContext; default strategy is thread-local storage per request.
Authentication Object — An interface holding the principal (user), credentials (password), and granted authorities of the currently authenticated user.
Principal — The identity of the currently authenticated user, typically the UserDetails object or username string stored in the Authentication object.
PasswordEncoder — An interface for encoding and verifying passwords; BCryptPasswordEncoder is the recommended implementation for secure hashing.
BCryptPasswordEncoder — Spring Security's recommended password encoder that uses the BCrypt adaptive hashing algorithm with salt, making brute-force attacks computationally expensive.
JWT Header — The first part of a JWT token encoded in Base64, containing the algorithm (e.g., HS256) and token type.
JWT Payload (Claims) — The second part of a JWT token containing the claims: subject (username), issued-at, expiration, roles, and any custom data.
JWT Signature — The third part of a JWT token created by signing the encoded header and payload with a secret key to verify integrity.
JWT Secret Key — A private key (or secret string) used to sign and verify JWT tokens; must be kept confidential and rotated periodically.
JWT Expiration — A claim (exp) in the JWT payload defining the timestamp after which the token is no longer valid and must be rejected.
Refresh Token — A long-lived token issued alongside the access JWT, used to obtain a new access token after it expires without re-authenticating.
Access Token — A short-lived JWT sent with every API request in the Authorization header to prove the user's identity and permissions.
Bearer Token — An authentication scheme where the client sends the JWT in the HTTP header as `Authorization: Bearer <token>`.
Stateless Authentication — An approach where no session is stored on the server; every request is self-authenticated using the JWT it carries.
OAuth2 — An open authorization framework that allows third-party applications to obtain limited access to a user's account without exposing credentials.
OAuth2 Resource Server — A Spring Security configuration that validates incoming JWT Bearer tokens and protects API endpoints from unauthorized access.
OAuth2 Authorization Server — The server responsible for authenticating users and issuing access tokens, refresh tokens, and authorization codes.
OAuth2 Client — An application that requests access to a protected resource on behalf of a user using tokens obtained from the authorization server.
Authorization Code Flow — The most secure OAuth2 flow where the client receives an authorization code via redirect and exchanges it for tokens server-side.
Client Credentials Flow — An OAuth2 flow for machine-to-machine communication where the client authenticates using its own ID and secret, not a user.
Implicit Flow — A deprecated OAuth2 flow where tokens were returned directly in the URL fragment; replaced by Authorization Code with PKCE.
PKCE (Proof Key for Code Exchange) — An OAuth2 extension that prevents authorization code interception attacks in public clients like SPAs and mobile apps.
OpenID Connect (OIDC) — An identity layer on top of OAuth2 that returns an ID token (JWT) with user profile information alongside the access token.
ID Token — A JWT issued by an OIDC provider containing identity claims (name, email, sub) about the authenticated user.
Scope — A parameter in OAuth2 that defines the level of access requested by the client (e.g., read, write, openid, email, profile).
Keycloak — An open-source identity and access management server that provides OAuth2, OIDC, SAML, SSO, and user federation out of the box.
Spring OAuth2 Login — A Spring Security feature that enables social or enterprise login via OAuth2/OIDC providers like Google, GitHub, or Okta.
CSRF Token — A unique, unpredictable token included in every state-changing request to verify it originated from the legitimate application, preventing CSRF attacks.
CSRF Protection — Spring Security enables CSRF protection by default for web apps; it should be disabled for stateless REST APIs using JWT.
CORS Configuration — Spring Security's CORS support that must be configured to allow cross-origin requests from frontend apps before security filters run.
@EnableWebSecurity — Annotation that enables Spring Security's web security support and allows customization via a SecurityFilterChain bean.
@EnableMethodSecurity — Annotation (replaced @EnableGlobalMethodSecurity) that enables method-level security annotations like @PreAuthorize and @PostAuthorize.
@PreAuthorize — A method-level annotation that evaluates a Spring Expression Language (SpEL) expression before the method is invoked to control access.
@PostAuthorize — A method-level annotation that evaluates a SpEL expression after the method returns, allowing access control based on the return value.
@Secured — A simpler method-level annotation that restricts access based on a list of role names (e.g., @Secured("ROLE_ADMIN")).
@RolesAllowed — A JSR-250 annotation equivalent to @Secured for restricting method access by role, supported via @EnableMethodSecurity.
Role — A coarse-grained permission label prefixed with ROLE_ (e.g., ROLE_ADMIN, ROLE_USER) assigned to a user to control broad access.
Permission (Authority) — A fine-grained privilege string (e.g., user:read, order:delete) assigned to a user for precise access control beyond roles.
hasRole() — A SpEL method in @PreAuthorize that checks whether the current user has a specific role (automatically adds ROLE_ prefix).
hasAuthority() — A SpEL method in @PreAuthorize that checks whether the current user has a specific authority or permission string exactly as given.
hasAnyRole() — A SpEL method that returns true if the current user has at least one of the specified roles.
isAuthenticated() — A SpEL expression that returns true if the current user is authenticated (not anonymous).
isAnonymous() — A SpEL expression that returns true if the current user has not been authenticated.
permitAll() — A security rule that allows all users including unauthenticated ones to access the specified endpoint.
denyAll() — A security rule that blocks all users including authenticated ones from accessing the specified endpoint.
antMatchers() / requestMatchers() — Methods used in HttpSecurity to match URL patterns and apply authorization rules (antMatchers deprecated in Spring Security 6, replaced by requestMatchers).
Session Management — Spring Security's ability to control session creation strategy: ALWAYS, IF_REQUIRED, NEVER, or STATELESS for JWT-based APIs.
SessionCreationPolicy.STATELESS — Configures Spring Security to never create or use an HTTP session, required for stateless JWT-based REST APIs.
Remember Me — A Spring Security feature that persists authentication across browser sessions using a persistent token stored in a cookie and database.
Logout — Spring Security's built-in logout support that invalidates the session, clears the SecurityContext, and optionally deletes cookies on logout.
Basic Authentication — An HTTP authentication scheme where the username and password are base64-encoded and sent in the Authorization header with every request.
Form Login — Spring Security's built-in form-based login support that processes a POST to /login with username and password parameters.
ExceptionTranslationFilter — A Spring Security filter that handles AuthenticationException (triggers login) and AccessDeniedException (triggers 403 response).
AuthenticationEntryPoint — An interface invoked when an unauthenticated user attempts to access a protected resource; returns a 401 Unauthorized response.
AccessDeniedHandler — An interface invoked when an authenticated user lacks permission to access a resource; returns a 403 Forbidden response.
MethodSecurityExpressionHandler — The component that evaluates SpEL expressions in @PreAuthorize and @PostAuthorize annotations for method-level security.
InMemoryUserDetailsManager — A UserDetailsService implementation that stores user details in memory; suitable for testing and development only.
JdbcUserDetailsManager — A UserDetailsService implementation that loads user credentials and authorities from a relational database via JDBC.
SecurityMatcher — Restricts a SecurityFilterChain to apply only to requests matching a specific URL pattern, allowing multiple filter chains for different API areas.
Multiple Security Filter Chains — A Spring Security pattern where different filter chains (e.g., one for /api/, one for /admin/) apply different rules to different URL groups.
Content Security Policy (CSP) — An HTTP security header configurable in Spring Security that restricts which sources of content (scripts, styles) the browser can load.
HSTS (HTTP Strict Transport Security) — A security header Spring Security adds by default to force browsers to always use HTTPS for future requests to the domain.
X-Frame-Options — A security header Spring Security sets by default to prevent clickjacking by controlling whether the page can be embedded in an iframe.
X-Content-Type-Options — A security header that prevents browsers from MIME-sniffing a response away from the declared Content-Type, set by Spring Security by default.
Security Headers — A set of HTTP response headers (CSP, HSTS, X-Frame-Options, etc.) automatically added by Spring Security to protect against common web attacks.
IP-Based Access Control — Spring Security's ability to restrict endpoint access based on the client's IP address using hasIpAddress() in SpEL expressions.
Two-Factor Authentication (2FA) — An additional security layer requiring a second verification step (e.g., OTP) after password validation, implementable as a custom filter.
LDAP Authentication — Spring Security's support for authenticating users against an LDAP directory server, common in enterprise environments.
SAML — Security Assertion Markup Language; an XML-based SSO protocol supported via Spring Security SAML for enterprise identity federation.
SSO (Single Sign-On) — A session/authentication scheme that allows a user to log in once and access multiple applications without re-authenticating.
Delegating Password Encoder — Spring Security's DelegatingPasswordEncoder stores the encoding algorithm ID with the hash (e.g., {bcrypt}$2a$...) allowing multiple encoders simultaneously for migration.
Password Migration — Spring Security supports upgrading legacy password hashes (MD5, SHA) to BCrypt transparently at login time using DelegatingPasswordEncoder.
Method Security — The ability to secure individual service or repository methods using annotations (@PreAuthorize, @Secured) rather than only URL patterns.
Global Method Security — Application-wide activation of method-level security, enabled via @EnableMethodSecurity so annotations are enforced across all beans.
Anonymous Authentication — Spring Security creates an anonymous Authentication object for unauthenticated users so filters and expressions can handle them consistently.
RunAs Authentication — A Spring Security mechanism that temporarily replaces a user's Authentication with a different one during a method call for privilege escalation scenarios.
Security Event Publishing — Spring Security publishes events (AuthenticationSuccessEvent, AuthenticationFailureEvent, etc.) to the ApplicationContext for logging and auditing.
Audit Logging — Capturing and storing authentication and authorization events (login success/failure, access denied) for compliance and security monitoring.

Strategy changes algorithm externally; State changes behavior internally.

Adapter changes interface; Decorator adds functionality.

Factory and Singleton patterns.

Proxy pattern.

Template Method pattern.
